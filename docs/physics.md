# Physics model

## Units and spacetime

V1 uses geometrized units with the Schwarzschild radius

\[
r_s = \frac{2GM}{c^2} = 1.
\]

The exterior metric is

\[
ds^2 = -\left(1-\frac{1}{r}\right)dt^2
       +\left(1-\frac{1}{r}\right)^{-1}dr^2
       +r^2(d\theta^2+\sin^2\theta\,d\phi^2).
\]

Because Schwarzschild spacetime is spherically symmetric, each photon trajectory lies in a plane through the origin. With `u = 1/r`, the null-geodesic orbit can be represented by

\[
\left(\frac{du}{d\phi}\right)^2 = e^2-u^2(1-u),
\]

where `e` is the inverse impact-parameter constant in these units. The critical value is

\[
e^2 = \mu = \frac{4}{27},
\]

which corresponds to the unstable photon sphere at `r = 3/2` and the critical shadow impact parameter

\[
b_c = \frac{1}{\sqrt{\mu}} = \frac{3\sqrt{3}}{2}r_s.
\]

## Constant-time beam tracing

Numerically integrating the geodesic for every pixel every frame is accurate but expensive, especially for rays that orbit near the photon sphere. V1 follows Bruneton's precomputed beam-tracing method:

- `D(e, u)` stores accumulated deflection and coordinate time.
- `U(e, φ)` stores inverse radius and coordinate time along the ray.
- nonlinear texture-coordinate mappings concentrate precision at the critical orbit and apsis.
- the fragment shader queries ray deflection plus up to two thin-disk intersections in constant time.

The 512×512 `RG32F` deflection table and 64×32 `RG32F` inverse-radius table were generated by the reference implementation through numerical geodesic integration. Their checksums are recorded in `public/assets/README.md`.

## Observer

The camera is a static observer at radius `r > r_s`. Its four-velocity is

\[
u^\mu_{obs} = \left((1-1/r)^{-1/2}, 0, 0, 0\right).
\]

Screen rays are constructed in the observer's local orthonormal tetrad before being transformed into the pseudo-Cartesian frame used by the lookup algorithm. The current UI intentionally prevents a static observer from approaching the horizon, where infinite proper acceleration would be required.

## Accretion disk

The disk is a zero-torque, geometrically thin model extending from the Schwarzschild ISCO `r_in = 3 r_s` to `12 r_s`. Its effective temperature is proportional to

\[
T_{eff}(r) \propto
\left[
\frac{1-\sqrt{r_{in}/r}}{r^3}
\right]^{1/4}.
\]

The profile vanishes at the ISCO, peaks at `49/12 r_s`, and then decreases approximately as `r^{-3/4}`. The user control sets the peak temperature.

Matter follows circular equatorial motion. At every ray/disk intersection the renderer evaluates the emitter-to-observer frequency ratio

\[
g = \frac{\nu_{obs}}{\nu_{emit}}
= \frac{k_\mu u^\mu_{obs}}{k_\mu u^\mu_{emit}},
\]

which combines gravitational redshift and orbital Doppler shift. Since `I_ν/ν³` is invariant and a shifted black body remains a black body, the observed visible spectrum is sampled at `T_obs = g T_eff` from a CIE/Planck lookup table.

The animated density filaments are procedural and are advected with the Schwarzschild Keplerian angular-rate dependence `Ω ∝ r^{-3/2}`. V1.1 samples a continuous Cartesian noise field after a logarithmic spiral twist, then uses a small domain warp and ridge transform to avoid periodic radial bands. The resulting density perturbs effective temperature, emissivity, and optical depth. It provides spatial detail; it is not a fluid or GRMHD simulation.

## Celestial background

Escaped rays sample an equirectangular ESO/S. Brunier Milky Way panorama, so the same Schwarzschild geodesic mapping lenses the background and the disk. The panorama supplies visual context only: its orientation is presentational, and it is not a Gaia-calibrated astrometric or photometric sky model.

## Display pipeline

The shader returns linear HDR radiance. User exposure, an ACES-style curve, and linear-sRGB conversion map it onto an ordinary display. These steps preserve relative physical effects but do not define an absolute astronomical exposure.

## Validation anchors

Automated tests pin the following independent analytic facts:

- `r_ph = 1.5 r_s`;
- `b_c = 3√3/2 r_s`;
- `r_ISCO = 3 r_s`;
- the thin-disk temperature maximum is at `49/12 r_s`;
- the static observer tetrad is orthogonal and has the correct radial lapse;
- lookup coordinate mappings place the two critical branches and apsis correctly.

The upstream project additionally compares its precomputed texture queries against direct numerical integration. V1.2 will add image-level comparisons against both that renderer and an independent CPU oracle.
